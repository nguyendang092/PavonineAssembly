0. TÓM TẮT KIẾN TRÚC (1 TRANG)
================================================================================

Stack:
  - React 18 + Vite
  - React Router v6
  - Firebase Auth + Realtime Database (RTDB) + Storage
  - i18next (vi / ko)
  - Tailwind CSS + CSS module theo feature

Luồng tổng quát mọi trang:

  main.jsx
    → ThemeProvider, LoadingProvider
    → App.jsx
        → đọc localStorage.userLogin (phiên 30 phút)
        → onValue(userDepartments) → userRole, userDepartments
        → BrowserRouter
            → Navbar (menu từ menuConfig.js)
            → #app-main-scroll (vùng cuộn chính)
                → Suspense (LoadingBlock)
                    → Routes
                        → ProtectedRoute (trừ /login)
                        → ProductionPageShell (hầu hết route) HOẶC trang độc lập (/)
                            → lazyImport() page component
                                → hook load Firebase (onValue / get)
                                → useMemo / derived state
                                → render bảng / chart / form

Hai cách load Firebase chính:
  A. REALTIME  — onValue(ref) → cập nhật state mỗi khi DB đổi
     Dùng: điểm danh theo ngày, giờ công ngày, khuôn, nhiệt độ, MC defect, …
  B. ONE-SHOT  — get(ref) hoặc query range → fetch một lần (có thể cache)
     Dùng: dashboard kỳ, báo cáo ngày, lưới tháng giờ công, snapshot kiểm kê

Hai layout sidebar:
  - Production sidebar  — productionSidebarConfig.js (hầu hết route)
  - HR sidebar (legacy) — AttendanceListShell (chỉ khi route KHÔNG thuộc production layout)

Tài liệu HR chi tiết (đã gộp trong file này):
  - PHỤ LỤC A — Phép năm
  - PHỤ LỤC B — Lưới tháng giờ công
  - docs/FIREBASE_DATABASE.md, docs/GIO_CONG_TINH_TOAN.md (tham chiếu ngoài)

3.3 Khi dùng onValue vs get
───────────────────────────
  ┌─────────────────┬──────────────────────────────────────────────────────┐
  │ onValue         │ Dữ liệu cần realtime, nhiều user cùng sửa           │
  │ (listener)      │ VD: điểm danh ngày, payroll ngày, mold list         │
  ├─────────────────┼──────────────────────────────────────────────────────┤
  │ get             │ Snapshot một lần, báo cáo, dashboard kỳ             │
  │ (one-shot)      │ VD: daily report, attendance dashboard, month grid  │
  ├─────────────────┼──────────────────────────────────────────────────────┤
  │ query+onValue   │ Range theo key (phép năm — attendance cả năm)       │
  │                 │ annualLeaveLiveStore.js — dedupe listener             │
  ├─────────────────┼──────────────────────────────────────────────────────┤
  │ Repository      │ Firebase + localStorage + pending queue             │
  │                 │ manualEntriesRepository.js (S90D/AP5)                 │
  └─────────────────┴──────────────────────────────────────────────────────┘

  Cleanup bắt buộc:
    useEffect(() => {
      const unsub = onValue(ref, callback);
      return () => unsub();
    }, [deps]);

  Chống race condition:
    generation counter (useAttendanceDayFirebase)
    startTransition cho update không khẩn (payroll reconcile)

A.5 CÔNG THỨC TÍNH PHÉP
────────────────────────────────────────────────────────────────────────────────

A.5.1 Phép năm hiện tại (annualLeaveCurrentYear)
  annualLeaveCurrentYear = monthlyAccrual + tenureBonus + adjustment

  monthlyAccrual : +1 PN/tháng (theo quy tắc bên dưới)
  tenureBonus    : +1 PN mỗi 5 năm thâm niên
  adjustment     : HR chỉnh tay (annualLeaveAdjustment)

  File: annualLeaveCalculated.js → resolveAnnualLeaveCurrentYear

A.5.2 Quy tắc +1 PN/tháng (accrual)
  File: annualLeaveCalculated.js → resolveAnnualLeaveMonthlyAccrualDays
        monthMeetsHalfStandardWorkDays

  Điều kiện "đạt nửa tháng" (monthMeetsHalfStandardWorkDays):
    Đạt MỘT trong hai:
      - Tổng ngày công (gồm nghỉ có lương) >= 1/2 "Ngày thực tế làm việc"
      - Số ngày nghỉ thai sản >= 1/2 "Ngày thực tế làm việc"

  Nguồn ngày công tháng:
    buildAnnualLeaveMonthWorkSummary (annualLeavePayrollAccrual.js)
    → buildMonthlyRuleSummary (payroll) — cùng logic bảng giờ công

  Theo giai đoạn:
    T6/2026 trở đi (và mọi tháng năm >= 2027):
      Mọi NV: +1 PN CHỈ KHI tháng đó đạt 1/2 ngày công
      Cộng ngay khi đạt, kể cả tháng hiện tại (không chờ hết tháng)

    T1–T5/2026 (quy tắc cũ):
      NV cũ     : +1 auto mỗi tháng trong khoảng
      NV mới    : tháng vào làm cần đạt 1/2; các tháng khác +1 auto

  Khoảng tháng tính: từ max(ngày vào làm, 1/1 năm) đến hôm nay (năm hiện tại)
                     hoặc 31/12 (năm đã qua)

A.5.3 Phép đã dùng & còn lại
  annualLeaveUsed = HR used + attendance PN
                    (hoặc tổng monthlyLeaveUsage nếu merge Excel)

  totalAnnualLeave = currentYear + bonusEnv + compensatoryDayOff (+ thành phần khác)
  balance          = totalAnnualLeave - annualLeaveUsed

  Gộp theo tháng (buildAnnualLeaveMonthlyUsageByEmpKey):
    Tháng 1–5 : ưu tiên monthlyLeaveUsage từ Excel (Firebase)
    Tháng 6+  : lấy từ điểm danh (PN, ½PN)

  File: annualLeaveDerived.js → computeLiveAnnualLeaveState
