0. TÓM TẮT NHANH (1 TRANG)
================================================================================

Hai root RTDB chính:

  attendance/{yyyy-mm-dd}/{emp_{mnv}}     Bản ghi điểm danh theo ngày
  annualLeave/{year}/emp_{mnv}          Bản ghi phép năm (stored)
  annualLeave/{year}/_meta                Metadata năm (updatedAt, rowCount, …)

Nguyên tắc:

  • Sửa điểm danh → LUÔN ghi attendance trước (update 1 node).
  • Phép năm KHÔNG tự ghi mỗi lần render UI — chỉ ghi khi có trigger sync.
  • Sau sửa loại phép điểm danh → queue sync 1 NV (debounce 450 ms).
  • Sau xóa / upload Excel điểm danh → sync cả năm (quét attendance).
  • HR sửa cột «Điều chỉnh» → ghi thẳng annualLeave 1 NV (không qua queue).
  • Nút «Tính lại» / upload Excel phép → sync cả năm.

Bảng trigger → hàm → phạm vi:

  Trigger                              Hàm chính                         Ghi gì
  ─────────────────────────────────────────────────────────────────────────────────
  Lưu form điểm danh                   update attendance                 attendance
                                       + applyAnnualLeaveDeductionDelta  annualLeave (1 NV, queue)
  Thêm NV mới (form)                   update attendance                 attendance
                                       + applyAnnualLeaveDeductionDelta  annualLeave (1 NV, queue)
  Xóa 1 dòng điểm danh                 remove attendance                 attendance
                                       + persistAnnualLeaveYear…         annualLeave (cả năm)
  Xóa cả ngày (Admin)                  persistAnnualLeaveYear…           annualLeave (cả năm)
                                       + remove attendance/{date}        attendance
  Upload Excel điểm danh               set attendance/{date}             attendance
                                       + persistAnnualLeaveYear…         annualLeave (cả năm)
  Ngày off / lễ / nghỉ bù             update …/{date}/_meta             _meta only (không sync phép)
  HR sửa «Điều chỉnh» phép             persistAnnualLeaveEmployeeAdj…    annualLeave (1 NV)
  Nút «Tính lại» phép năm              persistAnnualLeaveYear…           annualLeave (cả năm)
  Upload Excel phép năm                update annualLeave/{year}         annualLeave (merge)
                                       + persistAnnualLeaveYear…         annualLeave (recalc)
  Xóa dữ liệu năm phép                 remove annualLeave/{year}         xóa cả năm

Skip sync phép (chỉ ghi attendance):

  attendanceRootPath = seasonalAttendance   (điểm danh thời vụ)
  attendanceRootPath = koreanAttendance     (điểm danh Hàn)

    • Trường trong dayDoc ghi đè.

    • Luôn có id = firebaseKey.

  Build logic: src/utils/attendanceEmployeeRecord.js
    buildEmployeeAttendanceDayDocument()
    mergeAttendanceDayNodeForPersist()

3.3 Sync phép sau lưu điểm danh
────────────────────────────────

  syncAnnualLeaveAfterAttendanceSave(oldRecord, newLoaiPhep)
    │
    ├─ shouldSkipAnnualLeaveForAttendanceRoot? → return (không sync)
    │
    └─ applyAnnualLeaveDeductionDelta(db, {
         year: annualLeaveYearFromDateKey(selectedDate),
         attendanceRootPath,
         updatedBy: user.email,
         oldRecord,
         newLoaiPhep,
       })

  applyAnnualLeaveDeductionDelta (annualLeaveAttendanceSync.js):
    1. oldLp = loại phép cũ (từ oldRecord hoặc oldLoaiPhep)
    2. newLp = loại phép mới (từ newRecord hoặc newLoaiPhep)
    3. delta = deduction(newLp) − deduction(oldLp)
    4. delta === 0 → { applied: false, reason: "no_delta" }  (KHÔNG ghi phép năm)
    5. Có empKey từ oldRecord/newRecord
         → queueSingleEmployeeAnnualLeavePersist (debounce 450 ms)
    6. Không resolve được empKey
         → fallback persistAnnualLeaveYearFromAttendance (cả năm)

  Lưu ý:
    • Đổi giờ vào/ra, ca, tên, … KHÔNG trigger sync nếu loại phép không đổi.
    • Đổi loại phép PN ↔ 1/2PN ↔ khác → có delta → queue sync 1 NV.

3.4 Sơ đồ ASCII — Luồng A
──────────────────────────

  [User: Lưu form điểm danh]
            │
            ▼
  buildEmployeeAttendanceDayDocument + mergeAttendanceDayNodeForPersist

8. LUỒNG F — SYNC PHÉP NĂM (CORE)
================================================================================

File trung tâm: src/features/leave/annualLeaveAttendanceSync.js

8.1 persistAnnualLeaveYearFromAttendance — sync cả năm
──────────────────────────────────────────────────────

  Call sites:
    • AnnualLeaveManager.handleRecalculate (nút «Tính lại»)
    • AnnualLeaveManager.handleUpload (sau merge Excel phép)
    • useAttendanceListMutations (xóa NV / xóa cả ngày)
    • AttendanceUploadHandler (upload Excel điểm danh)
    • applyAnnualLeaveDeductionDelta (fallback khi không có empKey)

  Tham số:
    db, year, attendanceRootPath = "attendance", updatedBy, attendanceRootOverride?

  Các bước:
    1. get(attendanceRootPath) — toàn bộ cây attendance (hoặc override)
    2. buildAttendanceAnnualLeaveDerivedMaps(data, year)
         → deductionsByEmpKey, attendanceMonthlyByEmpKey
    3. get(annualLeave/{year})
    4. migrateAnnualLeaveYearToEmpKeys() nếu _meta.migrated !== true (legacy → emp_{mnv})
    5. indexAnnualLeaveYearByEmpKey(yearData)
    6. buildAnnualLeaveMonthWorkSummaryByEmpKey(...) — accrual +1/tháng từ giờ công
    7. Với MỖI empKey trong yearData:
         state = computePersistStateForRaw(raw, empKey, year, maps)
         needsPersistUpdate(raw, state)? → skip nếu không đổi
         Gom payload vào batch (bước 6)
    7b. 1 NV đổi → runTransaction; ≥2 NV → update(ref(db), multi-path) — 1 round-trip
    8. Nếu có ít nhất 1 NV đổi → touchAnnualLeaveYearMeta

  Trả về: { results[], appliedCount }

8.2 persistSingleEmployeeAnnualLeaveFromAttendance — sync 1 NV
────────────────────────────────────────────────────────────

  Gọi từ: annualLeavePersistQueue (sau debounce)

  Giống sync cả năm nhưng:

    • monthWorkSummary scopeEmpKeySet = { empKey }
    • Luôn touch _meta nếu có thay đổi

8.3 applyAnnualLeaveDeductionDelta — sau đổi loại phép form
─────────────────────────────────────────────────────────────

  Xem mục 3.3. Chỉ queue 1 NV khi delta ≠ 0.

8.4 migrateAnnualLeaveYearToEmpKeys — migration key
───────────────────────────────────────────────────

  Chỉ chạy nếu annualLeave/{year}/_meta/migrated !== true (bước 7).
  Tự chạy đầu persistAnnualLeaveYearFromAttendance / persistAnnualLeaveMonth…

  Ghi:
    annualLeave/{year}/emp_{mnv} = { ...raw, id: empKey }
    annualLeave/{year}/{recordId} = null   (xóa key cũ)
    annualLeave/{year}/_meta/migrated = true   (sau lần đầu — bỏ scan legacy)

  19. Bước 4 — runTransaction cho annualLeave/{year}/{empKey}
================================================================================

  Vấn đề race condition:
    Hai luồng ghi (form điểm danh + CF / upload / điều chỉnh HR) có thể cùng
    đọc snapshot cũ rồi update() — ghi đè lẫn nhau, mất cộng/trừ PN.

  Giải pháp:
    runAnnualLeaveEmployeePersistTransaction() trong annualLeaveAttendanceSync.js
    • runTransaction(ref, mutator) trên annualLeave/{year}/{empKey}
    • Mutator đọc current mới nhất, computeLive → needsPersistUpdate
    • return undefined → abort (không ghi)
    • Firebase tự retry khi conflict — không cần client debounce để «đúng số»

  Debounce 450ms (annualLeavePersistQueue.js):
    Vẫn giữ để giảm số transaction khi user gõ nhanh — tối ưu chi phí, không
    thay thế cơ chế an toàn của transaction.

  Điểm gọi transaction:
    • persistAnnualLeaveForEmployeeKeys — 1 NV đổi (xem bước 6 batch khi ≥2)
    • persistAnnualLeaveEmployeeAdjustment — điều chỉnh HR (patch trong mutator)
    • attendanceLeaveAgg — đã dùng transaction từ bước 1
    • Cloud Function persistEmployee.mjs — đã dùng transaction từ bước 2

  _meta và migrate vẫn dùng update() — không cạnh tranh cộng/trừ số dư.
